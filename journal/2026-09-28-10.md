## What this run did

This was the second cycle of the scheduled run that began at 12:44 UTC. (A "cycle" is one unit of work that gets its own pull request and is merged before the next one starts.) The first cycle's pull request, #118, merged before this one began.

The mode selector (the script that decides what each cycle does) chose **lint**, which it forces every five runs. A lint pass does no new writing. It runs every mechanical check over the whole dictionary and then rereads the knowledge base (the `wiki/` folder of rules, decisions, and notes) for contradictions, stale claims, and gaps. This was the twentieth pass.

**The mechanical checks.** The word caps on the rule files hold, and every link inside the knowledge base resolves. The cross-reference tool, which keeps "synonym", "opposite", and "compare" links symmetric between entries, added no links. It did report one mismatch, and the cause was my own first cycle. In that cycle I changed *would*'s link to *used to* from "compare" to "synonym". But *used to* listed *would* as both a synonym and a word to compare, so the two entries disagreed. *used to* now lists *would* as a synonym only, with the note that explains the difference moved onto that link. The vocabulary check (which makes sure definitions use only plain words that have entries) found no problems. It did add one bad row to the queue of words waiting for entries: *straighten* as a noun, taken from the definition of *jump*, where it is really a verb. *straighten* is already queued as a verb, so I marked the noun row as a duplicate. No stale claims (words reserved by a run that never finished) were found.

**Reviewer precision.** Each lint pass measures how often each reviewer's objections turn out to be right, by kind of objection. When a kind of objection from one reviewer has been right less than 30 percent of the time over at least twenty decisions, the rule is to switch it off. The first reviewer's objections about inflections (word forms such as *ran* or *children*) reached that line this time: right once in 21 decisions (5 percent). All the others were rejected because the reviewer misread forms that the dictionary's rules and exceptions table generate. That kind of objection is now switched off for the first reviewer, the sixth pair switched off since 2026-09-19. The second reviewer still checks inflections. The first reviewer's pronunciation objections, right 33 percent of the time over 119 decisions, are now the closest to the line.

**The reread.** The index lists every page, no index link is dead, and the file of questions for you (`reviews/needs_curator.txt`) has no duplicate lines. One line in `NEXT.md` (the short to-do note each run leaves for the next) was itself out of date. It told you that two old branch-cleanup lines in the curator file were stale, but those lines had already been moved to the file's "Resolved" section. I removed the line from `NEXT.md`.

I also looked into a message that appeared when this run fetched the repository: "forced update" on `main`. That message usually means history was rewritten. Here it did not. The container had started with a very old copy of `main` from before an earlier history change. Every entry from that period is still in the dictionary, and the current `main` holds all of this week's work.
