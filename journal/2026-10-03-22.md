This was the second cycle of the run that started at 20:43 UTC. A *cycle* is one unit of work that is checked, recorded, and merged on its own; the first cycle (a second reading of twelve verbs, *stop* to *survive*) merged as pull request #214.

The selector (`tools/next_mode.py`, the script that picks each cycle's job) forced a **lint** pass, because five cycles had passed since the last one. A lint pass is a health check of the whole dictionary and its knowledge base: the mechanical checks are run over everything, and then a person-style reading looks for what a script cannot see, such as contradictions between pages or links placed on the wrong sense. It costs nothing, because it calls no outside model.

## Back-links

Cross-references in this dictionary go both ways: if *alarm* lists *fear* as a synonym, *fear* should list *alarm* too. The tool `crossref.py` adds the missing return link (a *back-link*), but it has to guess which sense of the target to attach it to, so every lint pass checks each one by hand.

This pass added fifteen. Eleven were right (for example *bug* on the "something wrong with a machine" sense of *fault*, and *court* on the sport sense of *field*). Four were not:

- Three re-created links that the previous cycle's review had deliberately removed from one side only. In that review I took *break* out of *stop*'s synonyms (on a reviewer's advice), *feed* out of *supply*'s, and *exist* out of *survive*'s first sense, but *break*, *feed*, and *exist* still pointed back, so the tool restored the pairs, on the wrong senses. The rule already in `NEXT.md` says a review that removes a link must remove its mirror too; I had not done so. I have now removed the links from *break* and *feed* as well. For *exist* ("stay alive with very little food or money"), the link was in fact right, so it now sits on *survive*'s first sense, which holds *survive on very little*.
- The link from *work* ("have the result that you want") had been placed on *fail* "stop working". It now sits on *fail* "not succeed", its true opposite.

No *type mismatches* were reported (a pair listed as synonyms on one side and as "compare" on the other).
