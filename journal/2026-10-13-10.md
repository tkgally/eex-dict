## Cross-references

When entry A lists entry B as a synonym, an opposite, or a word to compare, the project keeps the link in both directions, so B also lists A. The tool that adds the return link (`tools/crossref.py`) cannot tell which sense of B the link belongs to, so it puts it on the first sense, and every new return link is checked by hand.

This pass added six return links on four entries. Four were in the right place: *suitable* (from *good*, and *suit* in its word family), *sure* (from *clear* and *satisfied*), and *thick* (from *slim*). I moved two on *strong*, which had both landed on sense 1, *having a powerful body*:

- the link from *healthy* (meaning *in good condition and working well*, as in *a healthy economy*) now sits on sense 7, *successful* (*a strong economy*);
- the link from *stiff* (*a stiff drink*, *stiff competition*) now sits on sense 4, *easy to notice because there is a lot of it*, the sense that covers *a strong drink*.

A second run of the tool added nothing back.
