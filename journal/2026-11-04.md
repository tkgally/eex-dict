# Run report, 2026-11-04

## Cycle 1: site

**What this cycle did.** The scheduler (`tools/next_mode.py`, which picks each cycle's kind of work from whichever kind is most overdue) chose a site cycle. Its reason was "highest scheduler debt among eligible modes": of the six kinds of work it can choose (building new entries, reviewing existing ones, closure, site, lint, and the originality check), the site check had gone longest relative to how often it should run. A site cycle writes no entries. It rebuilds the public website from the entry files and then opens the result in a real browser to check that it works.

**Before the work.** The usual pre-flight checks found nothing waiting. There were no open pull requests left behind by an earlier run (a pull request is the proposed change that GitHub tests and then merges into the published copy), no leftover working branches, no entry reports from readers (these arrive as GitHub issues titled "Entry report: ..."), and nothing in `inbox/`, the folder where you leave instructions. The day's spending budget had just reset at midnight UTC: yesterday closed at US$3.92 of the US$15 daily cap.

**The build.** `tools/build_site.py` turned all 3,675 entries into 3,083 headword pages; an entry is one word in one part of speech, so a word like *run* with a noun and a verb entry shares a page. It wrote 6,818 files in all (entry pages, the search index, previews and the home page). No drafts had to be held back, because every entry is reviewed, and there are no redirects (pages for renamed words).

**The check.** `tools/site_check.py` drives a headless Chromium browser at a phone width (360 pixels) and a desktop width (1,280 pixels). It ran 79 checks and all 79 passed. Among them:

- No page scrolls sideways at phone width. All 3,089 pages were tested, not a sample.
- Search finds a headword from an inflected form (*ran* finds *run*), finds a phrase from its key words, and offers "Did you mean" for a misspelling (*abadnon* suggests *abandon*).
- Pressing Enter opens the first result, and an address like `?q=ran` fills in the search box and runs the search.
- The address of a missing page (for example, `w/runxx.html`) gives a styled 404 page that searches for the name.
- Hovering over a linked word in a definition opens a short preview.
- The translator's view (a toggle that shows notes meant for translators) opens, stays open after a reload, and closes again.
- Dark mode has a dark background. The sense menu on long entries jumps to the right meaning.
- A cross-reference to a word that has no entry yet is shown in grey, not as a link, with the legend that explains it.

No JavaScript errors were reported during any of these steps. Nothing was broken, so nothing in the site builder or its templates changed. The built site (`docs/`) is never committed: GitHub Actions rebuilds it after the merge.
