# Journal, 2026-11-13 (third run of the day, run m3t3kf)

## Cycle 1: site

**What the cycle was for.** Each cycle of a scheduled run does one job, chosen by the mode selector (`tools/next_mode.py`, a script that picks whichever kind of work is most overdue). This time it chose *site*: rebuild the public website from the dictionary's entry files and check it in a real browser. A site cycle writes no entries and makes no paid model calls. Its selector reason was "highest scheduler debt among eligible modes", which means that of all the jobs allowed to run, the site check had waited longest relative to how often it is meant to run. The last site check was on 2026-11-12; since then three runs have added or changed entries (twelve family entries from *nursery* to *paste*, ten queue entries from *occasion* to *overtime*, and a coverage review of *single*, *sister*, *slow*, and *smell*), so a fresh check was due.

**Housekeeping before the work.** Every run first looks for work a previous run left unfinished. There were no open pull requests (a pull request is a proposed batch of changes waiting to be merged into the published `main` branch) and no open entry reports from readers. One old working branch, `claude/friendly-mayer-mdy32d`, still exists on GitHub; the branch-checking tool confirmed that everything on it is already in `main`, and it was already listed in `reviews/needs_curator.txt` for deletion (the run's tools cannot delete branches). The inbox, where the owner leaves instructions, was empty.

**What was done.** The build script (`tools/build_site.py`) turned all 4,281 entries into 3,577 headword pages (a headword page groups every entry for the same spelling, such as a noun and a verb, on one page). No entries were held back as unfinished drafts, because every entry in the dictionary is now marked `reviewed`, and there are no redirects (pages that send an old address to a renamed entry). In all, 7,840 files were written to the `docs/` folder, which is never committed to the repository: GitHub builds its own copy for publishing.

The browser check (`tools/site_check.py`) then opened the site in a headless browser at phone width (360 pixels) and desktop width and ran its 79 checks. All 79 passed. Among other things, they confirm that:

- no page scrolls sideways at phone width, checked on every entry page and the key pages (3,583 pages);
- the search box finds a phrase from its main words (*a catch in voice* finds *a catch in someone's voice*) and offers "Did you mean" for a misspelling (*abadnon* finds *abandon*);
- the "not found" page searches for the word in the address;
- the jump menu on long entries (five senses or more) lists the senses and moves to the chosen one;
- a cross-reference to a word that has no entry yet appears grey and unlinked, with a note explaining the grey;
- dark mode shows a dark background, and no page raises a JavaScript error.

I also checked by hand that the pages for words added or changed today exist: *nursery*, *passage*, *occasion*, *outlet*, and *smell* are all there.

**What the reviewers found.** Nothing: a site cycle does not use the reviewer models, so there were no review issues to decide.

**Spend.** US$0 in this cycle. The day's total stays at US$1.69 of the US$15 daily budget.

**What did not work.** Nothing failed. No change to the site templates or tools was needed.
